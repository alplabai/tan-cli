Re-capturing: crates/ is frozen and will not change again for this reason,
so there should be no reason to re-run the capture recipe above UNLESS a
NEW case is added to one of the five files it lists (a new argv, a new tree
shape). Capturing is additive -- `oracle_fixtures.resolve()` only ever adds
or overwrites the keys the run you did touch, so a partial capture (e.g.
`pytest tests/parity/test_flash_oracle_parity.py -k some_new_case`) is safe
and does not disturb any other module's fixture file.
