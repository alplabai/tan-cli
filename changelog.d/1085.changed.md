  primitive.** `render_to_envelope`'s template-example `board.yaml` read
  carried its own hand-written `except (OSError, UnicodeDecodeError)` block,
  byte-for-byte the same shape `document_guards.DocumentGuards.
  read_catalog_document` already used for the catalog's own read -- two
  definitions of "cannot read `<what>` at `<path>`: `<reason>`" that happened
  to still agree. Both now call a new `DocumentGuards.require_readable_text
  (path, *, what)`, with the message text unchanged.
  `_require_mapping_doc`/`_require_field`/`_require_key` (tan-cli#1073/#1082)
  and the catalog readers themselves (tan-cli#1084) were already on the
  shared register before this change; `_require_constraints` stays local (no
  caller outside `template.py`'s own parameter resolution), and so do
  `_load_som_doc`/`_board_route_entries`/`_docs_ref` -- each has a caller (or
  two) within `template.py` already, just none in a different module, which
  is the register's actual bar for sharing. `template.py` itself is **not**
  smaller for this: it grew net +405 lines against its tan-cli#1025 starting
  point across the family's five prior rounds (only tan-cli#1084 ever
  removed anything), and this change trims 3 more lines off that total --
  closing the one remaining cross-module duplication this family's own
  #1085 named, not reversing the growth.
