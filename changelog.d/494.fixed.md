- **`tan.planner.template._derive_pin_doc_renames` no longer silently drops a
  pin's documentation when two `pins:` entries share one `doc:` string**
  (tan-cli#494 defect 9). Unlike its two siblings (`_derive_pin_renames` /
  `_derive_pin_macro_renames`, which both raise `TemplateError` on an
  ambiguous re-derive), the `doc:` companion had two unguarded assignment
  sites; a shared `doc:` that resolved to two different targets (or where one
  side had no target `doc:` at all — `None`, meaning DROP the field) silently
  kept whichever resolution ran last, decided purely by `pins:` ordering in
  the source file. Worst case, the pin WITH a good re-derived `doc:` lost it
  because the OTHER pin's target route had none. Ported verbatim from the
  upstream fix (`alplabai/alp-sdk#1399`, closes alp-sdk#1394) into
  `tan/planner/template.py`, which is a hand-audited mirror of
  `scripts/alp_template.py` and cannot pick up an upstream fix automatically.
  Not reachable through today's shipped catalog (no `board.yaml` in
  `metadata/templates/catalog-v1.json` has a duplicated `doc:` within one
  `pins:` list), so this closes a latent hazard rather than a live one.
