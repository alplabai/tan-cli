- **`tan probe`: a read-only J-Link command, so the bench no longer needs raw `JLinkExe`.** `tan probe identify [--core m55_he|m55_hp]` connects with the exact DPIDR preflight script `tan flash` uses, then runs the `--ram` attach check (`connect` plus two read-only `mem32`), and reports `identity.{dpidr,expectedDpidr,dpidrMatch,apAddr,cpuid,core,itcmVerdict,isolation}`; with a built project it compares the DP IDR with the manifest slice's `expect_dpidr` (`probe.dpidr-mismatch`, exit 1). `tan probe read <addr> [words]` runs one `mem32` (default 4 words, at most 256: `probe.read-too-large`), accepts only plain hex or decimal (`probe.bad-argument`) and returns the words as hex in `read.data`. It refuses 0x50000000-0x5FFFFFFF when the selected or attached core is the M55-HE, or the attach cannot be confirmed to be the M55-HP (`probe.read-unsafe-region`): an HE session must not touch that window. Probe selection, the trusted J-Link binary and the `ShowEmuList` verification are the `tan flash` ones (`--probe-usb-path`, `--probe-serial`, `--jlink`, `--build-root`, `--project`). No `probe` script can contain a write, erase, `loadbin`, `setpc`, `go`, reset or `w1`/`w2`/`w4`; a test scans every generated script for those verbs. New codes: `probe.read-too-large`, `probe.read-unsafe-region`, `probe.bad-argument`, `probe.unknown-verb`, `probe.read-failed`, `probe.failed`, `probe.dpidr-mismatch`, `probe.dpidr-unread`, `probe.internal-failure`.
