- **`assemble_changelog.py --check` now reads a fragment's body, not only its
  filename.** It validated the `<issue>.<category>.md` contract and stopped
  there — a fragment whose entire content was the single line
  `not a bullet at all` (the case measured on tan-cli#791's review) passed
  clean, `rc 0`, same fragment listing as every real entry. `splice()` never
  reformats a fragment: it joins bodies verbatim under a `### <Category>`
  heading, so a body that is not already a valid Markdown bullet list lands
  in `CHANGELOG.md` as bare prose sitting under a bullet-list heading. New
  `fragment_shape_errors()` catches that shape, not the prose inside it —
  whether a claim is true stays a review problem, not a gate problem — and is
  shared by `load_fragments()`, so `--check`, `--require-empty` and the real
  fold all refuse the same malformed content, naming the file and the
  offending line rather than exiting silently. All 33 fragments pending in
  `changelog.d/` at the time were re-checked against it and pass unchanged.
