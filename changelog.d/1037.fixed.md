- **A malformed `metadata/boards/<board>.yaml` no longer crashes `--emit
  scaffold` with a raw `AttributeError`, at the outer document shape or the
  nested `e1m_routes:` field.** `tan/planner/template.py`'s
  `_board_route_entries` (shared by `_board_alias_to_entry` and, through it,
  `_resolve_pin_target`) had no `isinstance(dict)` guard at either level
  before its bare `.get(...)` reads. Measured on the unguarded code: a
  `metadata/boards/<board>.yaml` that parses to a bare list raised
  `AttributeError: 'list' object has no attribute 'get'` from the outer
  `.get("e1m_routes")`; a well-formed board document whose `e1m_routes:`
  field itself is not a mapping raised the same class of error one line
  deeper, from the per-section `.get(section)`, reachable through
  `tan ... --template peripheral|sensor|edge-ai --sku E1M-V2N101`. Both now
  raise the module's own curated `TemplateError` naming the board path and
  the actual type, mirroring the `_load_som_doc`/`_topology_for_sku` guard
  shape (#1025, #1034).

  `_docs_ref`'s `metadata/sdk_version.yaml` read gains the same
  `isinstance(dict)` guard, degrading to `main` (as a missing/unreadable
  file already does) rather than raising `AttributeError: 'list' object has
  no attribute 'get'` on a bare-list document -- a README doc-link decision
  is not a fatal scaffold input.
