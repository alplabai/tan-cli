- **Three low-severity message and preflight fixes in `tan validate`, `tan bootstrap` and `tan diff`.**
  `tan validate` no longer calls an older bound alp-sdk "newer" with "rules added since not applied"; it orders the checkout against the audited commit with git, says the built-in validator may reject a board an older SDK accepts, and uses neutral wording when the order cannot be determined.
  The Windows 7-Zip preflight in `tan bootstrap` now checks the same binaries tan's own `.7z` extractor runs (`7z`, `7za`, `7zr`, `7zz`, `7zzs`), so a host with only `unar` is refused before the download instead of after it.
  `tan diff` no longer reports "board.yaml is not valid: the SDK's own validator rejects it" when tan's built-in validator itself crashed; it says the board could not be checked (tan-cli#1523).
