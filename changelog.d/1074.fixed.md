- **`Manifest.from_dict` now enforces `blob_format` against `VALID_BLOB_FORMATS` -- and the set itself was wrong, not just unenforced.** A manifest naming an unlisted `blob_format` (a typo'd `dxnn`, or a stale/foreign format string) used to decode clean; nothing in `python/tan/model/manifest.py` compared a decoded value against the frozenset it was declared to guard. Auditing every real producer before enforcing turned up the sharper half of the bug: `adapters/executorch.py`'s `ExecutorchAdapter` -- registered by default in `build.py`'s `_ADAPTERS`, reached automatically the moment a `board.yaml` `models[].source` ends in `.pte` -- emits `blob_format: "executorch"`, which was missing from `VALID_BLOB_FORMATS` even though the format is real, documented, and live. The set (not the adapter) was the thing that had drifted; enforcing it as originally declared would have rejected a package `tan model build` produces today. `VALID_BLOB_FORMATS` now includes `"executorch"`, reconciled against all five compiler-adapter emitters plus `_gen_fixture.py`'s `"onnx"` regression fixture, and an unlisted format now raises a curated `ValueError` naming the offending value and the accepted set.
- **`Manifest.from_dict` no longer lets a missing `name`/`src_sha` escape as a
  raw `KeyError`.** Both were still bare subscripts even after PR #1068
  curated every other decode path in `python/tan/model/manifest.py` into a
  `ValueError`; a mapping missing either key raised `KeyError('name')` (or
  `'src_sha'`) with no manifest context, not the "malformed .alpmodel
  manifest" framing the rest of this module's contract promises. Both now
  route through `_required_field`, and `src_sha` is checked against
  `from_dict`'s established post-normalisation contract (`bytes`, matching
  what `from_json` and `from_cbor` already hand it).
