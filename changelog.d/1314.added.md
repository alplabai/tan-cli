- **`tan flash` gains a `linux_mtd` backend that deploys a V2N / V2N-M1 CM33 image
  over the running Linux on the A55.** The CM33 image lives inside `mtd1` (the FIP
  partition) at `cm33_boot.xspi_offset` (0x1A0000), so tan erases and writes only
  that window (`flash_erase` over the image's blocks, then `mtd_debug write`) and
  never the partition; the offset and limits come from the SoC metadata's
  `cm33_boot` (or `flash_args`) and the run refuses without them. Before copying it
  checks the image is the padded CM33 image (zero pad, SP in SRAM0, Thumb reset
  vector, <= `image_max`), then it reads the window back with `mtd_debug read` and
  compares a sha256. The host comes from `flash_args.host` or `--target-host`;
  `flash_args.flash_partition` is required and never defaulted, `mtd0` is always
  refused, `/proc/mtd` must agree with the declared partition, and `--partition`
  must agree with the manifest. ssh/scp run with `BatchMode=yes`. The envelope
  records every step and the digest comparison and carries a `followUp` on what
  running the new image takes (tan does none of it). New codes `flash.linux-mtd-*`;
  see `docs/linux-mtd.md`. Not yet validated on silicon.
