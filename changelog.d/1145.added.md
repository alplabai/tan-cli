- **`scripts/audit_vacuous_loops.py` — find the loops and assertions in
  `python/tests/gates/` that never execute (#1145, second of two).** The first
  shape, a workflow `if:` key searched instead of compared, is a pure AST rule
  and ships separately. This one cannot be static: a loop over a collection
  that is EMPTY AT RUNTIME parses identically to one that iterates —
  `_gating_variables()` returning `{}` is the shape, and no parser sees it. So
  the script reads a coverage data file and reports every `for`/comprehension
  whose HEADER line executed while not one line of its BODY did, plus, from the
  same pass, every assertion whose own line never ran.

  Measured on a real run (`coverage run --source=tests/gates -m pytest
  tests/gates`, `1151 passed, 113 skipped`, 63 measured files): **10
  never-iterating loops and 105 never-executed assertions.** #1145's own audit
  predicted 7 against `d7c35dad` and named three of these exactly
  (`test_module_size_budget.py:348`/`:353`,
  `test_oracle_capture_store_is_labelled.py:145`); `dev` has moved 30+ commits
  since.

  **Ships in REPORT mode, `--check` unarmed and no CI leg** — the same shape
  `scripts/audit_narrow_except_contracts.py` has had since it was written (869
  lines, human-driven, never in CI). `DECLARED_EMPTY` is deliberately empty,
  because populating it is the judgement rather than the bookkeeping: coverage
  cannot tell "empty because the gate PASSES" (`for match in
  pattern.finditer(text)` finding no offenders) from "empty because the gate
  MEASURES NOTHING". Both are header-covered/body-not. Only a human separates
  them, and a row whose reason was guessed is what `test_hand_port_tan_side.py`
  calls "an exemption wearing a comment". #1145 stays open for that pass and
  the parallel `vacuity` job that follows it.

  **A real blind spot, asserted rather than left to be rediscovered.** A
  ONE-LINE comprehension puts its `elt` and generator conditions on the same
  line as its header, so line-granularity coverage cannot separate "iterated"
  from "did not". The detector skips those instead of guessing — reporting
  would false-positive on every one-line comprehension in the tree — and
  `test_a_one_line_comprehension_is_undecidable_and_is_skipped` pins the
  limitation so it reads as a known boundary rather than as coverage. It was
  found by the detector's own negative control while it was being built, which
  is the argument for having built the controls first.

  Ten controls ship with it, because #1145 names the hazard precisely: *"a
  meta-gate for this defect class can become the thing it detects — if its scan
  silently stops matching, it reports zero candidates and goes green."* Not
  hypothetical here: `audit_narrow_except_contracts.py` shipped 869 lines of
  AST logic with no coverage of its own and had to be retrofitted in PR #1138.
  Every control feeds FABRICATED source and a FABRICATED covered-line set, so
  none depends on a coverage run, on the gate suite, or on which tests happened
  to skip — positive controls for the never-iterating `for` and the multi-line
  comprehension; negative controls for a loop that ran, for a loop inside a
  SKIPPED test (header uncovered — a skip is not a vacuous loop, and 33 of
  #1145's 37 dead assertions were inside `ALP_SDK_ROOT` skips), and for the
  multi-line `if` body that keying on `body[0].lineno` would false-positive on,
  which #1145 records as its audit's only two false positives and is why this
  detector keys on the union of the whole body subtree. `--check` against an
  ABSENT coverage file exits **2**, never 0: reporting zero findings from a
  measurement that never happened is exactly how this class of gate goes quiet.
