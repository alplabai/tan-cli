- **`tan model doctor`.** Under alp-sdk ADR-0028 the `.alpmodel` compiler-adapter
  engine moved into tan, so tan is now the customer's only diagnostic surface for
  the NPU compiler toolchains `tan model build` shells out to. `model doctor`
  reports one row per registered backend (`cpu`/`ethos_u`/`drpai`/`deepx_dxm1`) --
  `{backend, tool, available, version, reason}` -- by calling each adapter's own
  `is_available()`, never a compiler: `vela not on PATH; pip install ethos-u-vela`,
  `dxcom not on PATH; license-gated, Linux-only`, or the real env var
  (`ALP_DRPAI_TVM_HOME`) an absent DRP-AI toolchain is missing. An unavailable
  toolchain is the expected case, not a failure -- `ok` stays `true` and exit
  code `0` even when every non-`cpu` backend is unavailable; reporting absence is
  the feature. A missing or rejected `--sdk-root` is a `model.doctor-sdk-unresolved`
  WARNING, never a crash or a refusal -- the backend rows do not read
  `metadata/**` and are unaffected either way. `tan model check` (a fit verdict
  against a board's declared models and `metadata/npu_ops/`) is a separate,
  not-yet-approved command and is not part of this change.
