- **`.alpmodel` manifest decoding now reports a malformed document as a
  curated error, not an internal one.** `Manifest.from_json` and
  `Manifest.from_cbor` bare-subscripted their decoded document (`d["src_sha"]`,
  `d["name"]`) with no `isinstance(d, dict)` guard -- the same defect class
  tan-cli#1018 fixed for `resolve_targets()`'s `preset["silicon"]` read.
  Measured on the unguarded code: a bare-list JSON/CBOR manifest raised
  `TypeError: list indices must be integers or slices, not str`; a
  bare-scalar manifest raised `TypeError: string indices must be integers,
  not 'str'`. Both shapes now raise a curated `ValueError` naming the actual
  type instead (`malformed .alpmodel manifest: expected a JSON object/CBOR
  map, got <type>`), reached through `Manifest.from_json`/`from_cbor`
  directly and through `package.read_manifest_file`/`read_package`, which
  decode a manifest region off an untrusted `.alpmodel` container. `.alpmodel`
  packages are machine-generated binary/CBOR artifacts, not hand-authored
  documents, but `package.py`'s own bounds-checked header reads already treat
  their bytes as wire data rather than trusted first-party output; a corrupt
  or truncated manifest region now fails the same way -- loudly, with a
  named field and type -- rather than surfacing a raw `TypeError` a caller
  cannot distinguish from any other bug in the call stack.
