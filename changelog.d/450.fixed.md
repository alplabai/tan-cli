- **The packaging path is now exercised by every pull request, not only by a
  pushed tag.** `release.yml` triggers on `v*` and nothing else, so two checks
  ran there and nowhere else: `tests/conformance/test_packaged_binary.py` and
  the glibc floor scan. A break in either was discoverable only by pushing a
  tag, and a tag cannot be un-pushed. That is how `v0.5.0` published nothing —
  `#349` switched the freeze to `--onedir`, the floor scan kept reading
  `.build/tan/PKG-00.toc`, `build` failed, `release` (`needs: build`) was
  skipped, and the tag was left spent with zero assets:

  ```
  no GitHub Release was published for v0.5.0 (release job: skipped). A pushed tag
  must always produce a Release with its assets; the tag is now spent with nothing
  behind it.
  ```

  No new workflow was added. `clean-host.yml`'s `freeze-and-smoke` job already
  freezes the same artifact in the same `python:3.12-slim-bullseye` container on
  every pull request, so it runs the same two commands — the exercise costs
  three lines rather than a second freeze that could drift from the shipping
  recipe. The size ceiling needed nothing: `scripts/build_binary.sh` sources
  `scripts/artifact_ceilings.env` and enforces it itself, so the existing PR
  freeze already covered it.

  The scan itself moved out of the workflow into
  `python/scripts/glibc_floor_scan.py`. That is what makes both halves possible:
  the two legs call one file instead of keeping two copies in step, and the
  refusal became unit-testable off a runner. Per the issue's non-vacuity
  requirement, `tests/scripts/test_glibc_floor_scan.py` drives the pre-fix shape
  and asserts the message, not merely the exit code:

  ```
  payload scan found 2 native files / 3 GLIBC_ versions under dist/tan/ -- refusing to guess a floor
  ```

  against the healthy tree's `payload floor over 63 native files: GLIBC_2.30`.

- **A stray apostrophe in a workflow's `docker run … bash -euc '…'` body can no
  longer reach a runner.** Those bodies are single-quoted shell inside a YAML
  scalar, so an apostrophe in a comment closes the string: `yaml.safe_load`
  still parses the file, every linter still passes, and the job dies at
  runtime — on a tag, for `release.yml`. `tests/gates/test_packaging_path_pr_exercise.py`
  now shells `bash -n` over every such body in `release.yml` and
  `clean-host.yml`, alongside pinning that both legs invoke the one extracted
  scan and that neither inlines a copy of it again.
