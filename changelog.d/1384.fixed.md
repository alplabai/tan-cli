- **The workspace patch-check cache no longer weakens silently, and now fingerprints files a patch deletes.** `_patched_files` returned a partial list when a `zephyr/patches/<entry>` could not be read, so the cache key degraded toward HEAD-only and a `west patch clean` or `git checkout -- .` revert of the dropped files went unnoticed. It now returns `None` on any read error and on an empty list, and `tan build` skips the cache and runs the verifier. It also collects `--- a/<path>` so a file a patch deletes (`+++ /dev/null`) moves the key when a revert restores it.
