- **`test_the_breadth_layer_still_covers_every_board` no longer reds under
  `pytest-xdist`.** Fixes `#1256`. `_ARTEFACTS_COMPARED` is a module-level
  dict fed by two parametrized tests and read once, at the end, by the
  breadth-floor test, which asserts `>= 90` boards and `>= 2900` artefacts.
  Serially that is one process, so the floor-check sees every board's
  contribution -- but each `pytest-xdist` worker is a separate process with
  its own copy of the dict, so whichever worker drew the floor test only
  ever saw that worker's own partial share and reported e.g. "only 54
  boards were measured" for reasons having nothing to do with the SDK's
  actual breadth. `parity.yml` runs the module whole and unsharded
  specifically so this floor means something, so shrinking it per shard was
  never on the table.

  Took the issue's option 2: `tests/parity/conftest.py` now has each xdist
  worker publish its own `_ARTEFACTS_COMPARED` share via
  `config.workeroutput` in `pytest_sessionfinish`, and the controller merges
  every worker's share as it shuts down (`pytest_testnodedown`,
  `node.workeroutput`) -- boards unioned, per-board counts summed, matching
  `_ARTEFACTS_COMPARED[name] += compared`'s own accumulation semantics --
  then enforces the same two floors against the merged total from its own
  `pytest_sessionfinish`, failing the whole session with a message naming
  `#1256` if either is short. The in-test assertion itself now skips outright
  on an xdist worker (`PYTEST_XDIST_WORKER` set) instead of judging a partial
  share; serial behaviour is untouched, and a session where the breadth test
  never ran at all (a `-k` that excludes it, or `tests/parity` not selected)
  stays silent on the controller side too, the same as the in-test
  `pytest.skip` for that case. `pytest_testnodedown` is registered with
  `optionalhook=True` so a plain, xdist-less `pytest` run does not error over
  a hookimpl for a hookspec that, in that run, does not exist.

  One trap along the way: collecting the whole `tests/parity` directory also
  collects `test_planner_axis_build_plan_parity.py`, which imports
  `tests.parity.test_planner_emit_parity` at its own module level --
  resolved, since `tests/__init__.py` does not exist, through Python's own
  namespace-package machinery into a SECOND, never-mutated module object for
  the same physical file. Reading `_ARTEFACTS_COMPARED` off "the first
  `sys.modules` entry matching that file" silently returned that empty
  duplicate whenever the whole directory was collected, reporting "only 0
  boards were measured" on a session where every board test genuinely ran.
  The worker-side lookup now sums `_ARTEFACTS_COMPARED` across every matching
  `sys.modules` entry rather than trusting whichever one import order
  happens to return first.
