- **`test_the_breadth_layer_still_covers_every_board` no longer reds --
  or silently passes -- under `pytest-xdist`, including a plain
  `pytest -n auto` over the whole `tests/` tree.** Fixes `#1256`.
  `_ARTEFACTS_COMPARED` is a module-level dict fed by two parametrized
  tests and read once, at the end, by the breadth-floor test, which
  asserts `>= 90` boards and `>= 2900` artefacts (`_BREADTH_MIN_BOARDS` /
  `_BREADTH_MIN_ARTEFACTS`). Serially that is one process, so the
  floor-check sees every board's contribution -- but each `pytest-xdist`
  worker is a separate process with its own copy of the dict, so whichever
  worker was assigned the floor test only ever saw that worker's own
  partial share and reported e.g. "only 54 boards were measured" for
  reasons having nothing to do with the SDK's actual breadth. `parity.yml`
  runs the module whole and unsharded specifically so this floor means
  something, so shrinking it per shard was never on the table.

  Took the issue's option 2: every xdist worker publishes its own
  `_ARTEFACTS_COMPARED` share via `config.workeroutput` in
  `pytest_sessionfinish`, and the controller merges every worker's share
  as it shuts down (`pytest_testnodedown`) -- boards unioned, per-board
  counts summed, matching `_ARTEFACTS_COMPARED[name] += compared`'s own
  accumulation semantics -- then enforces the same floors (read straight
  off the test module, so the two checks cannot drift apart) against the
  merged total, failing the whole session with a message naming `#1256`
  if either is short, or printing one "merged breadth floor OK" line if
  not. The in-test assertion skips outright on a worker, but only once a
  HANDSHAKE (`pytest_configure_node` stamping the worker's own
  `workerinput` before it starts) proves the merged check is actually
  loaded for this session -- any session where it is not falls straight
  through to the old, partial-share assertion instead of skipping
  silently.

  The hooks live in `tests/parity/_xdist_breadth_floor.py`, registered
  from `python/conftest.py`'s `pytest_plugins` -- the one file every
  invocation loads regardless of path -- so the controller side is never
  skippable by a narrower or absent path (`pytest -n N tests`,
  `tests/parity`, or no path at all all behave alike). The handshake means
  a session where that registration is somehow missing falls back to the
  old assertion loud instead of vanishing silently.

  One trap along the way: `test_planner_axis_build_plan_parity.py`
  imports `tests.parity.test_planner_emit_parity` at its own module
  level, which -- since `tests/__init__.py` does not exist -- resolves to
  a second, never-mutated module object for the same physical file; a
  `sys.modules` lookup by file identity could return that empty duplicate
  instead of the real one. Reading `_ARTEFACTS_COMPARED` off the actual
  collected test item's own `.module` instead sidesteps the ambiguity
  entirely.
