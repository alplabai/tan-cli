- **`tan model build`/`tan model check --exact` now check the SECOND half of
  a `Sram_Only` fit: the compiled blob's own residency in SRAM0, next to the
  arena.** Fixes #1288. The issue's own premise was wrong and is corrected
  here rather than re-litigated: it claimed tan already compared the vela
  arena (`req_sram_kib`) against `board.yaml`'s own budget "per #1011" -- it
  did not. #1011 was only the scope decision that `req_sram_kib` stays
  arena-only (alp-sdk#2312 confirms weights are never summed into it); no
  host-side comparison against `board.yaml` existed anywhere. This PR adds
  BOTH halves in one new module, `tan.model.sram_fit`: the arena check the
  issue believed already existed (`req_sram_kib` vs. `cores.<id>.inference.
  default_arena_kib`, or the schema default of 128 KiB when the board
  declares none), and the SRAM0 residency check it actually asked for
  (`ceil(len(blob.payload)/1024) + arena_kib` vs. the resolved SoC variant's
  `sram_banks_kb.SRAM0`) -- reusing `tan.core.size`'s existing variant/bank
  resolution rather than adding a second, potentially-drifting reader.

  Applies only under the ethos_u `Sram_Only` vela memory mode
  (`src/backends/inference/ethos_u_aen.cpp` pins every NPU access to the SRAM
  AXI port there); every other mode reports both checks `"skipped"`, with a
  reason. Never a bare `"fits"` -- every SoC ships `inference_arena_sram_kib:
  0` today, so a pass is always `"fits-unverified"`; only a `"no-fit"` is
  certain, plain ceil'd-KiB arithmetic against a real bank size.

  **Which `board.yaml` core the arena budget comes from is itself scoped, not
  guessed.** The E4/E6/E8 SoC specs declare NO `paired_core` for their own
  Ethos-U85 -- the flagship SKU's own headline compile target -- so a first
  cut that defaulted straight to the bare 128 KiB schema default there would
  have silently ignored the board's real `cores.m55_hp.inference.
  default_arena_kib` override on every real AEN SoM (review: the issue's own
  "72 vs 64" case would have falsely PASSED). Fixed by scoping certainty to
  what `board.yaml` actually declares: a target whose paired core (or, absent
  a pairing, the board's ONE declared inference-bearing core) `board.yaml`
  actually declares is CERTAIN and may refuse; several equally-plausible
  cores (no pairing, more than one declares `inference:`) only refuse past
  the largest of their budgets and only pass unverified below the smallest,
  skipping the ambiguous middle; and a paired core the board never declares
  at all, or a board with no inference core declared, SKIPS rather than
  refusing on an invented number.

  `tan model build` REFUSES the whole per-model build on a certain no-fit --
  no `.alpmodel` is written -- with the new `model.sram-no-fit` issue code at
  `ExitCode.VALIDATION_FAILURE`. `tan model check --exact` attaches a new
  `sramFit` envelope block to each ethos_u backend report (`arena`/`sram0`
  verdicts plus the KiB numbers) and raises the same issue/exit code on a
  no-fit; a static screen (no `--exact`) carries no `sramFit` at all -- there
  is no compiled blob yet to measure one against, and a matched
  `metadata/model_perf/` point carries it forward only when it corroborates
  an already-compiled report.
