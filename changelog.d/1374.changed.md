- **`diagnostics.link: itcm` now accepts `diagnostics.console: uart`.** A Flow C
  RAM-run with a UART shell works on AEN803 (bench 2026-10-07, e1m-aen-evk-02: `tan
  flash --ram` loaded the image at 0x0, shell on UART5), so the ITCM retarget no
  longer needs hand-copying into the app's overlay/conf. With `uart`,
  `alp-link-itcm.conf` carries only `CONFIG_USE_DT_CODE_PARTITION=n` and
  `CONFIG_FLASH_LOAD_OFFSET=0x0`, and `alp-link-itcm.overlay` is unchanged; the
  16 KiB `CONFIG_RAM_CONSOLE_BUFFER_SIZE` and `CONFIG_DCACHE=n` stay only for
  the RAM console (`auto` or `ram`, bytes unchanged). `alp`/`linux`/`none`
  remain `build.link-itcm-console-conflict`, whose message now names `uart` as
  an option.

  The bench hand-added only `zephyr,flash = &itcm;`, the code-partition delete,
  `CONFIG_USE_DT_CODE_PARTITION=n` and `CONFIG_FLASH_LOAD_OFFSET=0x0` -- no
  `CONFIG_DCACHE=n` -- so the UART5 shell ran with the D-cache at its board
  default. The D-cache hang recorded by #1350 concerns the RAM-console path,
  which still gets `CONFIG_DCACHE=n`. Refs #1374.
