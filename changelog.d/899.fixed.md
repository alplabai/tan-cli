- **`.github/zizmor.yml`'s two `artipacked` suppressions moved from
  `<file>:<line>` pins to inline `# zizmor: ignore[artipacked]` comments, so
  a rebase can no longer make them rot.** A line pin stops matching the
  moment anything above it moves. It rotted twice on the #770/#880 branch,
  pre-merge: net +21 lines (`release.yml:1202:9` → `1223:9`) when `dev`
  merged in, carrying both #876 (+49 lines above the pin) and #883 (-28
  lines above the pin) landed the same day, then +2 more from #880's own
  comment edit (`1223:9` → `1225:9`), caught only because the author
  happened to re-run `zizmor` after editing. Both rotations failed
  *loudly* — the gate went red on the very next run. Proved on this tree:
  inserting 60 filler lines above the `release.yml` `propose-dev-version-bump`
  checkout left the suppression matched and the gate at `rc=0`; removing
  either inline comment by hand reproduced a live `artipacked` finding and
  `rc=13` at exactly the now-unsuppressed step, then restoring it returned
  the gate to green. `.github/zizmor.yml`'s header keeps a hand-maintained
  inventory of both sites so the "one reviewed baseline in one file"
  property #435 built the file around survives the move — a reviewer still
  finds both exceptions by reading the header, not by grepping every
  workflow. Re-measured on zizmor 1.29.0, same invocation
  (`--min-severity medium --no-online-audits .github/workflows/`): `rc=0,
  15 ignored, 54 suppressed`, unchanged before and after.

- **New gate closes the quiet drift the inline form opened: a third
  `artipacked` suppression landing anywhere under `.github/workflows/` no
  longer escapes review silently.** The inline form fixes the LOUD rot (a
  moved pin makes the finding come back, gate red) but a new suppression
  needs no edit to the reviewed `.github/zizmor.yml` at all — measured,
  planting a third ignore leaves `zizmor` at `rc=0, 16 ignored, 54
  suppressed` (was 15), nothing naming the new exemption.
  `python/tests/gates/test_zizmor_inventory_count.py` counts the real
  inline `# zizmor: ignore[artipacked]` comments (a `uses:` line carrying
  one, not any comment that merely mentions the pattern) and compares
  against the numbered rows under `.github/zizmor.yml`'s own `INVENTORY --`
  heading. Mutation-proved: the planted third ignore fails the gate
  (`3 == 2` assertion), restoring the tree passes it clean. Renaming an
  inventoried step rather than adding one is a different drift this count
  check does not catch — closing that needs the inventory rewritten in a
  machine-parseable form, a bigger lift filed as a follow-up rather than
  built here (see `.github/zizmor.yml`'s own header for both notes).
