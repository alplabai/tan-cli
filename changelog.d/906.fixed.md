- **`MODULE_SIZE_BUDGET_LOG.md`'s "append-only" header is now enforced by a
  gate, not just prose.** Fixes `#906`. Nothing previously read the ledger's
  own git history: `test_module_size_budget.py` only ever parses the sibling
  `module_size_budget.generated.json`, so an existing entry could be silently
  edited or deleted and every local and CI gate stayed green -- exactly what
  happened on `#902`, where resolving a merge conflict with
  `git checkout --theirs` took `dev`'s side of the file wholesale and
  discarded the branch's own reasoned entry, found only by reading the diff
  by hand.

  The new `test_module_size_budget_log_append_only.py` compares the ledger's
  working-tree content against every commit the current PR/merge-queue run
  introduced since diverging from its base ref (`git rev-list
  <base>..HEAD`), each checked against its own git parents, and fails if any
  parent's lines are not still all present, in order. Each parent is checked
  as an ordered subsequence rather than a literal prefix on purpose:
  `.gitattributes`' `merge=union` on this file (`#939`) legitimately resolves
  two branches' divergent appends as "ours' new lines, then theirs' new
  lines", and -- measured directly against `dev`'s own history -- an
  ordinary single-parent squash-merge commit can produce the identical
  interleaved shape when a PR's branch regenerated its own ledger entry
  against an earlier `dev` snapshot. A literal-prefix check would have
  false-positived on both of those legitimate shapes; an edit, deletion, or
  reorder of a parent's own lines still breaks the subsequence check
  regardless, since the missing or moved line simply cannot appear in the
  same relative order.

  Comparing only against `HEAD`'s own immediate parents was tried first and
  measured to miss the shape `#906` was actually filed about: an ordinary
  commit landing on top of the damage, or GitHub's own
  `refs/pull/N/merge` checkout shape, both make HEAD's two immediate parents
  look clean even though an earlier commit on the branch dropped a line.
  Walking every commit since the PR's base ref closes both gaps. The base
  ref itself is read from `GITHUB_BASE_REF` (`pull_request`, set
  automatically by GitHub Actions) or a `TAN_MERGE_GROUP_BASE_REF` the
  workflow exports from `github.event.merge_group.base_ref` (`merge_group`,
  which GitHub Actions does not populate `GITHUB_BASE_REF` for); on any
  other trigger (a direct push, a release run) there is no separate base and
  the check falls back to `HEAD`'s own parents. A `pull_request` or
  `merge_group` run that cannot resolve its base ref fails the gate outright
  rather than silently falling back.

  A shallow (`fetch-depth: 1`) checkout previously made the enforcing test
  read every CI run as "HEAD has no parents (repo root commit)" and skip --
  which is exactly what every CI job that ran this suite was doing, since
  none of them fetched more than one commit. `fetch-depth: 0` on those jobs'
  checkouts and a dedicated `git rev-parse --is-shallow-repository` guard
  that hard-fails (never skips) close that gap.

  Two known-wrong shapes of the union driver itself -- two branches editing
  the *same* existing entry landing as a silent duplicate, and a delete
  racing an adjacent append being silently reverted, both documented in
  `.gitattributes` -- are deliberately left alone here rather than fought;
  addressing either is `#907`'s scope, not this gate's.

  Proven with hermetic throwaway git repos, not just reasoned about: one
  test reproduces the `#902` incident exactly (`git checkout --theirs`
  after a real conflict) and confirms the dropped entry is flagged; a
  second configures the same `merge=union` attribute, merges two branches
  that each append a different entry, and confirms the clean auto-resolved
  result is *not* flagged; a third covers a plain single-parent edit with no
  merge involved at all; a fourth reorders two existing entries with nothing
  deleted; two more reproduce the `#902` shape surviving one ordinary
  follow-up commit and surviving GitHub's own `refs/pull/N/merge` checkout
  shape, respectively, and confirm both are still caught.
