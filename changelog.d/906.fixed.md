- **`MODULE_SIZE_BUDGET_LOG.md`'s "append-only" header is now enforced by a
  gate, not just prose.** Fixes `#906`. Nothing previously read the ledger's
  own git history: `test_module_size_budget.py` only ever parses the sibling
  `module_size_budget.generated.json`, so an existing entry could be silently
  edited or deleted and every local and CI gate stayed green -- exactly what
  happened on `#902`, where resolving a merge conflict with
  `git checkout --theirs` took `dev`'s side of the file wholesale and
  discarded the branch's own reasoned entry, found only by reading the diff
  by hand.

  The new `test_module_size_budget_log_append_only.py` compares the ledger's
  working-tree content against each of the checked-out `HEAD` commit's own
  git parents (`HEAD^@`) and fails if any parent's lines are not still all
  present, in order. Each parent is checked as an ordered subsequence rather
  than a literal prefix on purpose: `.gitattributes`' `merge=union` on this
  file (`#939`) legitimately resolves two branches' divergent appends as
  "ours' new lines, then theirs' new lines", and -- measured directly against
  `dev`'s own history -- an ordinary single-parent squash-merge commit can
  produce the identical interleaved shape when a PR's branch regenerated its
  own ledger entry against an earlier `dev` snapshot. A literal-prefix check
  would have false-positived on both of those legitimate shapes; an edit or
  deletion inside a parent's own lines still breaks the subsequence check
  regardless, since the missing line simply cannot appear at all.

  Two known-wrong shapes of the union driver itself -- two branches editing
  the *same* existing entry landing as a silent duplicate, and a delete
  racing an adjacent append being silently reverted, both documented in
  `.gitattributes` -- are deliberately left alone here rather than fought;
  addressing either is `#907`'s scope, not this gate's.

  Proven both directions with hermetic throwaway git repos, not just
  reasoned about: one test reproduces the `#902` incident exactly
  (`git checkout --theirs` after a real conflict) and confirms the dropped
  entry is flagged; a second configures the same `merge=union` attribute,
  merges two branches that each append a different entry, and confirms the
  clean auto-resolved result is *not* flagged. A third covers a plain
  single-parent edit with no merge involved at all.
