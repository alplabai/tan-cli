- **A gate now catches a narrowed `except` clause silently breaking a
  function's own "never raises" / quiet-return contract.** Three PRs
  (#1096, #1110, #1114) shipped the same defect in one night, each caught
  only by human-directed review: `document_guards.read_catalog_document`
  narrowed `except (OSError, ValueError)` to `except OSError`, letting a
  `UnicodeDecodeError` (a `ValueError` subclass) escape a function whose
  docstring says "Never raises"; a `Path.exists()` pre-flight swallowed
  `ENOENT`/`ENOTDIR`/`EBADF`/`ELOOP` but not `EACCES`, so an unreadable
  directory re-raised `PermissionError`; `perf.read_perf_point`'s sibling
  reader narrowed to `except (OSError, yaml.YAMLError)`, missing
  `UnicodeDecodeError` again. `tests/gates/test_never_raises_contract_holds.
  py` seeds twelve functions across `tan/core` and `tan/model` -- both
  quiet-return contracts (`None`/`[]`/`set()` on every failure) and
  curated-raise contracts (exactly one declared exception type, never a raw
  stdlib one) -- and drives each against seven real broken-filesystem
  shapes: non-UTF-8 bytes, a directory where a file is expected, a parent
  path that is itself a file, an `ELOOP` symlink loop, `chmod 000` on the
  containing directory, a malformed document, and an absent path.

  The shape sweep that seeded this gate (an AST walk over every `try` in
  `python/tan/` narrower than the failure modes of the I/O it wraps, in a
  function documented as quiet-return) found three MORE live instances of
  the same trap beyond the four the tracking issue named, all fixed in the
  same change: `perf_apply._resolve_hw_rev`, `metadata_schema.
  validate_document`, and `scaffold.read_example_tree` each had an
  `is_file()`/`is_dir()` pre-flight check that itself raised a raw
  `PermissionError` on a permission-denied ancestor directory -- the exact
  `Path.exists()` trap #1110 fixed, just via a sibling stdlib call.
  `drpai._compiler_version` was missing `UnicodeDecodeError` the same way
  `perf_apply.py`'s two issue-named sites were, both also fixed here.
