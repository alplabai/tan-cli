- **The rendered-byte parity axis ADR-0026 §D requires is now checkable, not
  merely incidental.** `python/tests/parity/test_planner_emit_parity.py`
  already compared every hermetic renderer byte for byte against alp-sdk, but
  nothing pinned *which* `--emit` modes that comparison was required to cover
  — a mode quietly dropping out of `GENERATE_MODES` still left every per-board
  assertion green, and the breadth layer's `>= 2900` artefact floor has enough
  slack to absorb one mode's worth of loss (~100 artefacts) without noticing.

  Two changes, both in that one file: `MODES` split into `PLANNER_MODES`
  (`build-plan` alone — the "planner axis" §G step 6 deletes once `tan
  build` plans without an alp-sdk counterpart at all) and `RENDER_MODES` (the
  remaining six system-scoped emits — the "render axis" §D requires to
  survive that deletion), so the eventual deletion can drop one name without
  touching the other. And a new
  `test_the_render_axis_mode_set_is_fully_accounted_for`, which reads
  `metadata/emit-registry-v1.json` off the bound alp-sdk checkout and asserts
  every mode it declares is in exactly one of three states: rendered
  (`RENDER_MODES` union `GENERATE_MODES` union `tan.planner_emit.TREE_MODES`),
  a named exemption (`build-plan`, `kconfig` — non-hermetic, shells `west
  build` — and `scaffold` — vendored into `tan init`), or an unmeasured gap,
  which fails naming the mode. Mutation-proved: removing `("yocto-conf",
  ("yocto",))` from `GENERATE_MODES` leaves the pre-existing breadth-floor
  assertion green and reds the new test naming `yocto-conf` by itself;
  restoring it is green again.

  Skips loudly without `ALP_SDK_ROOT`/`ALP_SDK_PARITY_ROOT` bound — it inherits
  the module's existing `pytestmark`, the same one every other test in this
  file already relies on, so no new silent-pass surface was added.
