- **`tan renode --sim-mode --timeout 0` can now report `renode.sim-exited-early`
  instead of a blind pass.** The hold loop computed
  `deadline = time.monotonic() + timeout` and then guarded with
  `while time.monotonic() < deadline:` — at `--timeout 0` the deadline was
  already in the past the instant it was read, so the loop body (the only
  place `proc.poll()` was called) never ran even once. `early_exit` stayed
  `None` forever and the `renode.sim-exited-early` arm was structurally
  unreachable at a zero-length hold, regardless of how the child actually
  exited. `_run_sim` now polls the child once up front (a do-while shape) so
  a Renode that is already dead by the time the hold is reached is caught
  even at `--timeout 0` — but that up-front poll alone is still a race
  against a child crashing right around spawn time: an instrumented build
  measured it landing a mere ~48 microseconds before `_teardown_sim`'s own
  first poll, so any runner slow enough to lose the first race loses the
  second one too, and a genuinely slower crash (the reviewer's deterministic
  50ms-delayed-exit repro) is invisible to both.
  - The real fix is in `_teardown_sim`: its post-`quit()` grace loop already
    waits up to `_QUIT_GRACE_S` (1s) and already observes the child's real
    exit code — that observation was previously discarded. It is now
    returned, but only when it can be proven the exit was not a healthy
    response to our own `quit()` request (which would otherwise misreport a
    normal `--sim-mode` shutdown as `renode.sim-exited-early`): either
    `RenodeMonitor.quit()`'s write to the child's stdin failed (`OSError`/
    `ValueError`, previously swallowed silently — now surfaced as a `bool`
    return, proof the child was already gone before we even asked it to
    quit), or the grace loop observes a NONZERO exit code (a clean
    `quit`-driven shutdown always exits 0 in this contract; a nonzero code
    proves the death was unrelated to `quit`, even when it lands after
    `quit`'s write has already succeeded). A code of exactly 0, or no exit
    observed before the grace period expires and the child is force-killed,
    is never treated as early.
