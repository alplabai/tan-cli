- **`tan build --board` now writes a minimal `build/system-manifest.yaml`, so a
  plain Zephyr build can be sized, imaged and flashed through tan.** The
  manifest is normally projected from a board.yaml, which this route does not
  have, so tan wrote none and printed `skipped writing system-manifest.yaml`.
  It now writes the slice entry itself: the planner core id (the target's
  cluster segment resolved through the SoC JSON's `zephyr_cpucluster`, so
  `.../rtss_he` is `m55_he` and `.../rtss_hp` is `m55_hp`, not the Zephyr
  qualifier), the board target, the `zephyr.elf` / build-dir paths under
  `build/<slice>-zephyr/build/`, the per-slice status, and the
  `expect_dpidr` + `jlink_device` pair a planned slice carries, all read from
  `metadata/socs/**`. `flash_method` is `zephyr_west_flash`, as for every
  planned Zephyr slice. `jlink_flash_device` and `slot0_load_address` are
  deliberately not written: the address comes from the SoM preset's
  `memory_map:`, which a bare board target does not name, so MRAM programming
  stays a planned-project job. A target the SoC JSON does not describe
  (`native_sim`, no SDK) keeps the slice id and carries no flash profile. A
  real write failure on this route now surfaces as `build.manifest-write-failed`
  like any other build (#1370).
