- **A broken `metadata/e1m_modules/<sku>.yaml` or `metadata/boards/<board>.yaml`
  no longer crashes `--emit scaffold` with a traceback.** Both reads in
  `tan/planner/template.py` — `_load_som_doc` and `_board_route_entries` —
  went `is_file()` pre-flight → bare `read_text()` → bare `yaml.safe_load()`,
  with no `try` at any point, so a non-UTF-8 byte, a syntactically invalid
  document or an unreadable file escaped `emit_scaffold` as a raw
  `UnicodeDecodeError`, `yaml.parser.ParserError` or `PermissionError` —
  measured on 3.12.3, 3.13.15 and 3.14.7 alike — past a caller that catches
  `TemplateError` and nothing else. All three are now the curated
  `TemplateError` the contract promises, naming the file and what went wrong.
  The missing-file messages (`no metadata/e1m_modules/<sku>.yaml for sku
  <sku>`, and the board equivalent) are preserved byte for byte.
- **The `is_file()` pre-flight is deleted, not widened.** It was itself the
  tan-cli#1127 trap: against an unreadable parent directory `Path.is_file()`
  raises `PermissionError` on 3.12.3 and 3.13.15 and returns `False` on
  3.14.7, so the same file produced a raw traceback on two interpreters and,
  on the third, a curated message claiming a file that is right there does
  not exist. Classifying on the real exception gives one answer on all three:
  `FileNotFoundError` keeps the caller's own "no such file" message, and
  every other failure names the read.
- **A malformed template-example `board.yaml` is curated too.** Found by
  sweeping the module rather than fixing only the two sites reported:
  tan-cli#1116 hardened `render_to_envelope`'s READ and left the
  `yaml.safe_load` one line below it bare, so a `board.yaml` that decoded
  cleanly but did not parse still escaped raw. `yaml.YAMLError` is neither an
  `OSError` nor a `ValueError`, so nothing on that path had ever caught it.
- **The shape sweep can see this class now.** `scripts/audit_narrow_except_
  contracts.py` looked only for a `try` narrower than the I/O it wraps, so a
  site with no `try` was invisible to it — which is why two live sites
  survived a sweep, a gate and three reviews. It grows a third shape,
  `absent-try`, and a third tally line. Re-measured: **67 candidates / 1
  absent-try** without `--planner`, **85 / 6** with it, against 65 / n-a at
  the previous run. Run on the pre-fix tree it reports **87 / 9** and names
  all three sites above exactly, so the detector is not vacuous at that six.
  The five it newly finds inside `tan/planner/**` are candidates to read, not
  confirmed defects, and are not fixed here.
- **Both sites are seeded into the never-raises gate.** `tests/gates/
  test_never_raises_contract_holds.py` held nothing under `tan/planner/**`
  before, on the reasoning that seeding needs `bind_sdk_root`; the two live
  sites this issue found in a file whose neighbours were already fixed are
  what that reasoning cost. Nineteen seeds now, each driven against the real
  broken-filesystem shapes.
