- **`tan doctor`'s and `tan faultdecode`'s tool lookup now share the same
  hardened `%PATH%` walk as `tan build`/`tan flash`/`tan size`, closing the
  last two of the five independent hand-rolled copies tan-cli#510 warned
  about.** `doctor_cmd.on_path` no longer builds its own candidate list; it
  delegates to `tan.core.tool_lookup.resolve_tool` (`faultdecode_cmd` was
  already calling `doctor_cmd.on_path`, so it is consolidated by the same
  change). **Behaviour change:** on Windows, a bare extension-less identity on
  `%PATH%` is no longer a match ahead of its `%PATHEXT%`-suffixed siblings --
  `doctor`/`faultdecode` now agree with the build/flash/size paths (and the
  Rust oracle), which never accepted that candidate either. An
  executable-bit check (`os.access(..., os.X_OK)`) is also dropped on the
  Windows arm, where it never distinguished anything file existence did not;
  the POSIX arm still enforces it via `shutil.which`.
