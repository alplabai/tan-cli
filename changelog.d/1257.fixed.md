- **`scripts/ci/apt-bounded.sh` falls back to `archive.debian.org` when
  `deb.debian.org` has actually stopped serving a bullseye suite, not merely
  expired it** (tan-cli#1257, option 2 — option 1, the bullseye-only
  `Acquire::Check-Valid-Until=false` waiver, landed separately in #1273 and
  stays unchanged). The waiver only ever waives an *expiry*; a 404 is not an
  expiry, and once Debian actually retires bullseye from `deb.debian.org` the
  waiver alone would not help. This is reactive, bullseye-only, and stays
  inside the wrapper's existing shared step budget and retry accounting: when
  an `update` attempt's own output names `deb.debian.org` and shows apt's
  "does not have a Release file" or a literal `404  Not Found` — never a
  plain expiry, timeout, or transient failure, which keep today's retry
  unchanged — the wrapper repoints every `deb.debian.org/debian` and
  `deb.debian.org/debian-security` occurrence in `/etc/apt/sources.list` (and
  any `sources.list.d/*.list`/`*.sources`) at `archive.debian.org`, announces
  the rewrite loudly (a stderr `NOTICE` and a GitHub `::warning::`, both
  naming #1257), and retries. The rewrite is idempotent, so a step's second
  `apt-bounded.sh` invocation (`install` after `update`) sees the already-
  rewritten sources and never re-triggers it. Measured 2026-09-25:
  `archive.debian.org` now carries bullseye's `main` and `updates` suites
  (200), so both stay on the archive path unconditionally once rewritten —
  but not yet `bullseye-security` (still 404). Rather than silently dropping
  the security suite, if a retry after the rewrite shows the same "gone"
  signature but now naming `archive.debian.org`, the wrapper refuses to keep
  retrying a deterministically dead mirror and fails immediately with a named
  `FATAL` error, so a CI failure says outright that the security index is
  unavailable on both hosts instead of presenting as ordinary retry
  exhaustion. Verified live against `python@sha256:411fa4dcfdce7e7a3057c45662beba9dcd4fa36b2e50a2bfcd6c9333e59bf0db`
  (the exact digest `release.yml`/`clean-host.yml` pin) with `deb.debian.org`'s
  HTTP traffic proxied to a 404-only stub: the rewrite fires, `bullseye` and
  `bullseye-updates` fetch for real from `archive.debian.org`, and
  `bullseye-security` fails loudly exactly as designed.
