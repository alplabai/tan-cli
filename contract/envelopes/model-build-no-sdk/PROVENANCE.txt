What this case pins
--------------------
`tan model build --format json` from an empty directory: the REFUSAL when no
alp-sdk checkout resolves -- `ok: false`, `exitCode: 2`
(`ExitCode.VALIDATION_FAILURE`), one `model.sdk-root-unresolved` ERROR, and
`data` still carrying `build`'s own empty payload shape (`schemaVersion`/`sku`/
`built`) rather than a generic stand-in, so a consumer reading `data.built` off
a refusal envelope gets the same shape a completed run would give it
(`_empty_data`'s own contract). Captured in the same spirit as `presets-no-sdk`
and `generate-board-yaml-missing`: a refusal is a wire shape a consumer parses,
not an absence of one.

The refusal fires BEFORE the board.yaml is read (`_run_build` calls
`_require_metadata_sdk_root` then `_load_board`), which is also why this case
is the deterministic one: the `model.board-yaml-missing` alternative embeds an
ABSOLUTE path in `issues[].message`, and `normalise()` deliberately does not
rewrite message strings.

Fully deterministic: no host state is read, so no `env.json`.
