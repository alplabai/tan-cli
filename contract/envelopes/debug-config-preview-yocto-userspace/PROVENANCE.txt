Why the PREVIOUS recording was wrong
------------------------------------
It described the frozen Rust v0.4.1 oracle, not the binary that ships.

tan-cli#321 added `debug-config.gdbserver-address-unresolved`, an info-severity
notice emitted whenever the final `miDebuggerServerAddress` is still the
unresolved `<host>:<port>` placeholder — a runtime property of the deployed
board that no build can resolve. The frozen oracle predates the feature and
never emits it. The golden was never re-recorded; the difference was DECLARED,
as a `pytest.mark.xfail(strict=True)` entry in the harness's
`DELIBERATE_DIVERGENCE` map.

The recording was therefore not merely stale, it was SELF-CONTRADICTORY as a
published artefact: `contract/issue-codes.json:2423` registers
`debug-config.gdbserver-address-unresolved` and
`.github/workflows/release.yml`'s "Bundle the envelope contract" step publishes
that registry and this `expected.json` into the SAME
`envelope-contract.json` release asset — so the asset published a code in its
`issueCodes` list while its `envelopes["debug-config-preview-yocto-userspace"]`
told a consumer this command reports no issues at all. It reports one.

And, as with the four siblings, the strict xfail fails only on XPASS, so it
pinned nothing beyond "the envelope differs somehow". This case has no live
oracle-parity fixture: the tan-cli#321 issue itself is unit-pinned in
`python/tests/commands/test_debug_config_command.py`, but the rest of the
envelope — `data.configuration.program`, `cwd`, `MIMode`,

envelope-level gate on the Python side at all. `data.configuration` is the
